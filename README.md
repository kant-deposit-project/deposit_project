# 은행 정기예금 가입 예측 (Bank Marketing)

포르투갈 은행의 전화 마케팅 데이터(UCI `bank-full.csv`)로, **전화를 걸기 전에 알 수 있는 정보**만 써서 고객의 **정기예금 가입 여부(y)**를 예측합니다.
가입 고객을 놓치지 않는 것(**Recall**)을 중요하게 보고, 모델 선택은 불균형 데이터에 맞는 **PR-AUC** 기준으로 했습니다.

이 README의 숫자는 모두 `bank_marketing_clean_정리본.ipynb`의 출력 기준입니다.

## 최종 결과 요약

| 항목 | 내용 |
| --- | --- |
| 최종 모델 | **LightGBM** + 파생변수 2개 (하루 통화량, 누적 가입률) |
| 하이퍼파라미터 | learning_rate 0.01, n_estimators 1000, num_leaves 31, min_child_samples 50, subsample 0.7 |
| 클래스 가중치 | 1:2 (yes 가중치 3.77) |
| 임계값 | **0.5** (Train 5-fold에서 F1 최적값 0.495와 F1 차이가 0.001 미만이라 기본값 유지) |
| Train 5-fold | PR-AUC 0.4908 · F1 0.5165 · Recall 0.5826 · Precision 0.4640 |
| **Test 결과** | **PR-AUC 0.4957 · F1 0.5329 · Recall 0.6040 · Precision 0.4769** |
| 비교 기준 | 무작위로 예측할 때 PR-AUC = 0.117 (Test 가입률) |

모델이 "가입"으로 예측한 고객 1,340명의 실제 가입률은 **47.7%**로, 전체 가입률(11.7%)의 약 **4배**입니다. 전체의 약 15%에게만 전화해서 가입자의 60%를 찾을 수 있고, 가입 1건당 통화 수는 8.5통에서 **2.1통**으로 줄어듭니다.

## 2. 데이터 품질 확인

### 2-1. 결측치

표시상 결측(NaN)은 **0건**이었지만, `unknown`과 `pdays = -1` 형태의 **의미상 결측**이 있었습니다.

| 컬럼 | 건수 | 비율 | 판단 |
| --- | --- | --- | --- |
| job = unknown | 288 | 0.64% | 기록 누락 |
| education = unknown | 1,857 | 4.11% | 기록 누락 |
| contact = unknown | 13,020 | 28.80% | 기록 누락 (6월 84.9%, 5월 57.9%에 몰려 있음) |
| poutcome = unknown | 36,959 | 81.75% | 36,954건은 구조적 결측, 5건은 기록 누락 |
| pdays = -1 | 36,954 | 81.74% | 구조적 결측 |

- `pdays = -1`인 36,954행은 `previous = 0`(이전 캠페인 연락 없음)인 행과 **정확히 같았고**, 이 행들은 poutcome도 모두 unknown이었습니다. 이전 연락이 없어 값이 원래 존재하지 않는 **구조적 결측**입니다.
- poutcome unknown 중 나머지 **5건**은 이전 연락이 있는데 결과만 비어 있어 기록 누락으로 판단했습니다. 행 수가 5개로 적어 카이제곱 검정은 적용하지 않고 unknown 범주로 유지했습니다.

### 2-2. unknown 처리 근거 (카이제곱 독립성 검정, Train)

unknown을 지우거나 채울지 판단하기 위해, **unknown 그룹과 나머지 그룹의 가입률이 같은지** 검정했습니다. Test 정보가 들어가지 않도록 분할 후 **Train으로만** 했습니다.

- **귀무가설(H0):** unknown 그룹과 나머지 그룹의 가입률이 같다
- **대립가설(H1):** 두 그룹의 가입률이 다르다
- **판정 기준:** 유의수준 0.05

| 컬럼 | unknown 가입자 (관측 → 기대) | 카이제곱 통계량 | p값 | Cramér's V | 판정 | 처리 |
| --- | --- | --- | --- | --- | --- | --- |
| contact | 431 → 1,214.4 | 801.66 | < 0.001 | 0.149 | 귀무가설 기각 | unknown 자체가 "가입 가능성 낮음"이라는 정보 → **범주로 유지** |
| education | 198 → 175.0 | 3.43 | 0.064 | 0.010 | 기각 못함 | 최빈값(secondary)으로 채우면 가입률이 다른 그룹이 섞임 → **범주로 유지** |
| job | 29 → 28.0 | 0.01 | 0.915 | 0.001 | 기각 못함 | 0.7%(239행)로 적고 채울 근거가 없음 → **범주로 유지** |

모든 칸의 기대 빈도가 5 이상(최소 28.0)이라 카이제곱 검정의 사용 조건을 만족합니다.

### 2-3. 중복치

| 기준 | 건수 |
| --- | --- |
| 17개 컬럼 완전 중복 | 0건 |
| duration 제외 중복 | **16건** (15그룹, 관련 31행, 모두 y = no) |
| 입력은 같은데 y가 다른 그룹 | 0건 |

같은 행이 Train과 Test에 나뉘면 누수가 생길 수 있어 **16건을 삭제**했습니다. 삭제하지 않았을 때의 영향은 12장에서 따로 확인했습니다.

### 2-4. 이상치

분포가 한쪽으로 크게 치우친 컬럼이 있어(balance 왜도 8.36, campaign 4.90), 평균과 표준편차를 쓰는 Z-score 대신 사분위수를 쓰는 **IQR(1.5 × IQR 규칙)**로 탐지했습니다.

| 컬럼 | 왜도 | 범위 | IQR 이상치 | Z > 3 | 판단 |
| --- | --- | --- | --- | --- | --- |
| age | 0.68 | 18 ~ 95 | 487 (1.08%) | 381 | 실제 가능한 값 → 유지 |
| balance | 8.36 | -8,019 ~ 102,127 | 4,729 (10.46%) | 745 | 실제 가능 (음수 3,766건) → **로지스틱회귀만 캡** |
| campaign | 4.90 | 1 ~ 63 | 3,064 (6.78%) | 840 | 실제 가능 (10회 이상 1,462건) → **로지스틱회귀만 캡** |
| pdays | 2.62 | -1 ~ 871 | 8,257 (18.26%) | 1,723 | 약 82%가 이전 연락 없음이라 IQR = 0 → 구조적 결측으로 판단 |
| previous | 41.85 | 0 ~ **275** | 8,257 (18.26%) | 582 | **275는 입력 오류 → 1행 삭제** |
| day | 0.09 | 1 ~ 31 | 0 | 0 | — |

- `previous = 275`는 다음으로 큰 값들(41, 51, 55, 58)과 크게 떨어져 있어 입력 오류로 판단했습니다. 이 한 행을 빼면 previous의 왜도는 41.85에서 7.83으로 줄어듭니다.
- balance는 Z > 3 기준으로는 745건만 잡혀 IQR(4,729건)보다 훨씬 적었습니다. 극단값이 표준편차를 키워 Z-score 경계가 넓어진 것으로 보이며, IQR을 고른 근거와 맞습니다.
- `duration`(7.16%)은 누수 때문에 모델에서 빼므로 이상치 처리 대상에서 제외했습니다.

## 3. 전처리

### 3-1. 분할 전: 행마다 규칙으로 바꾸는 처리 (누수 없음)

| 처리 | 대상 | 이유 |
| --- | --- | --- |
| `pdays` -1 → 0 | 36,954행 | -1은 일수가 아니라 "이전 연락 없음". 원래 pdays = 0인 행이 없어 실제 값과 겹치지 않음 |
| `poutcome` unknown → `no_prev_campaign` | 36,954행 | 이전 캠페인이 없어 결과가 존재하지 않음 |
| `poutcome` unknown 유지 | 5행 | 기록 누락 |
| job · education · contact `unknown` | 그대로 | 별도 범주로 유지 (2-2 근거) |
| `previous = 275` 삭제 | 1행 | 입력 오류 |
| `call_date` 추가 | 컬럼 | 파생변수(하루 통화량, 누적 가입률)를 만들기 위한 날짜 |
| `duration` 제외 중복 삭제 | 16행 | Train · Test 중복 방지 |

→ 정제 후 **45,194행** (모델 입력: `duration` 제외 15개 컬럼 + `call_date`)

### 3-2. 분할 후: 기준값을 Train으로만 계산하는 처리

| 대상 | 변환 | 적용 모델 | 이유 |
| --- | --- | --- | --- |
| 범주형 9개 | 원핫 인코딩 | 전체 | 순서가 없는 범주 |
| 수치형 6개 | 표준화 | 전체 | 로지스틱회귀 계수 비교, SMOTE 거리 계산용 |
| balance, campaign | 1%·99% 분위수 캡 (`QuantileCapper`) | 로지스틱회귀 | 값의 크기가 계수에 직접 반영되어 극단값의 영향을 받을 수 있음 |
| `call_date` | 하루 통화량 (`CallsPerDay`) | 8장부터 | 학습 데이터의 날짜별 통화 비율 |
| `call_date` | 누적 가입률 (`CumRate`) | 10장부터 | 학습 데이터에서 첫 통화일 ~ 전날까지의 가입률 |

모든 기준값(범주 목록, 분위수, 평균, 표준편차, 날짜별 통화 수, 누적 가입률)은 **Pipeline 안에서 Train(교차검증에서는 학습 fold)으로만 계산**합니다. 원본 컬럼 기준 변환 후 입력 변수는 51개입니다.

상관계수가 작아도 구간별로는 패턴이 있는 변수가 있어, 상관계수만으로 변수를 고르지 않고 직선이 아닌 관계도 학습하는 트리 기반 모델을 함께 비교했습니다.

## 7. 클래스 불균형 처리

불균형 처리는 **학습 fold에만** 적용했습니다(imblearn Pipeline → 검증 fold에는 적용되지 않음).
비율 `1:3`은 처리 후 **yes : no = 1 : 3**이라는 뜻입니다. 클래스 가중치로는 yes 가중치 = 7.55 ÷ 3 = 2.52입니다(1:2 → 3.77, 1:1 → 7.55).

### 7-1. 로지스틱회귀 (5-fold 평균)

| 방법 | PR-AUC | F1 | Precision | Recall | 학습시간(초) |
| --- | --- | --- | --- | --- | --- |
| Baseline | 0.407 | 0.277 | 0.639 | 0.177 | 0.20 |
| Class Weight 1:3 | 0.406 | 0.406 | 0.523 | 0.331 | 0.22 |
| Class Weight 1:2 | 0.405 | 0.437 | 0.462 | 0.414 | 0.24 |
| Class Weight 1:1 | 0.404 | 0.371 | 0.265 | 0.622 | 0.21 |
| RUS 1:3 | 0.405 | 0.404 | 0.522 | 0.329 | 0.12 |
| RUS 1:2 | 0.404 | 0.440 | 0.463 | 0.419 | 0.11 |
| RUS 1:1 | 0.403 | 0.367 | 0.260 | 0.626 | 0.12 |
| SMOTE 1:3 | 0.404 | 0.410 | 0.529 | 0.335 | 0.33 |
| SMOTE 1:2 | 0.404 | 0.438 | 0.458 | 0.419 | 0.35 |
| SMOTE 1:1 | 0.402 | 0.366 | 0.258 | 0.627 | 0.49 |

### 7-2. 의사결정나무 (5-fold 평균)

| Baseline | 0.174 | 0.308 | 0.294 | 0.324 | 0.31 |
| Class Weight 1:3 | 0.175 | 0.309 | 0.298 | 0.320 | 0.31 |
| Class Weight 1:2 | 0.175 | 0.308 | 0.300 | 0.317 | 0.26 |
| Class Weight 1:1 | 0.176 | 0.308 | 0.306 | 0.311 | 0.26 |
| RUS 1:3 | 0.175 | 0.317 | 0.240 | 0.467 | 0.18 |
| RUS 1:2 | 0.174 | 0.314 | 0.222 | 0.539 | 0.16 |
| RUS 1:1 | 0.164 | 0.293 | 0.190 | 0.644 | 0.12 |
| SMOTE 1:3 | 0.176 | 0.314 | 0.287 | 0.346 | 0.42 |
| SMOTE 1:2 | 0.171 | 0.304 | 0.280 | 0.332 | 0.42 |
| SMOTE 1:1 | 0.171 | 0.303 | 0.275 | 0.338 | 0.60 |

### 7-3. 결론: 클래스 가중치 사용

- 세 방법 모두 **PR-AUC는 거의 그대로**였습니다(로지스틱회귀 0.402 ~ 0.407, 의사결정나무 0.164 ~ 0.176). 불균형 처리는 정보를 늘리지 않고, yes로 판정하는 기준(Precision ↔ Recall 균형)만 옮깁니다.
- 예: 로지스틱회귀 가중치 1:1에서 Recall은 0.177 → 0.622로 올랐지만 Precision은 0.639 → 0.265로 떨어졌습니다.
- **RUS**는 no 데이터를 많이 버리고, **SMOTE**는 결과가 비슷한데 느려서 **클래스 가중치**를 쓰기로 했습니다.

## 9. 파생변수 ① 하루 통화량 (`calls_per_day`)

### 가설

하루에 통화를 많이 건 날은 넓은 고객층에 일괄로 건 날이고, 적게 건 날은 선별한 고객에게 집중한 날이라 가입률이 다를 것이다.

| 그날 통화 수 (Train 5분위) | 행 수 | 가입률 |
| --- | --- | --- |
| 1 ~ 177통 | 7,366 | **35.1%** |
| 178 ~ 262통 | 8,352 | 7.2% |

| 313 ~ 413통 | 7,230 | 4.6% |
| 414 ~ 651통 | 7,088 | 6.1% |

1. 데이터에 연도가 없어서, 행 순서에서 월이 크게 줄어드는 지점(12월 → 1월)마다 연도 +1 (시작 2008년, **추정**).
2. 연-월-일로 `call_date`를 만들었습니다.
3. **`CallsPerDay` 변환기**가 학습 데이터의 날짜별 통화 **비율**(같은 날짜의 행 수 ÷ 학습 데이터 전체 행 수)을 계산합니다. 전체 데이터로 세면 Test 행이 섞이는 누수가 생기기 때문입니다.

### 가설과 정의

- **정의:** 학습 데이터에서 첫 통화일부터 **전날까지**의 가입률입니다(오늘은 제외, 이전 기록이 없으면 NaN).

### 누수 방지

- **`CumRate` 변환기**가 학습 fold의 정답만 날짜별로 누적합니다.

## 12. 임계값 결정 → 최종 Test 평가

### 12-1. 임계값 (Train 5-fold, Test 미사용)

`cross_val_predict`로 Train의 각 행을 "그 행이 검증 fold일 때" 예측한 확률을 구하고, F1이 가장 높은 임계값을 찾았습니다.

| 임계값 | Precision | Recall | F1 |
| --- | --- | --- | --- |
| **기본 0.5** | 0.4640 | 0.5826 | 0.5166 |
| F1 최적 0.495 | 0.4634 | 0.5857 | 0.5174 |

두 임계값의 F1 차이가 0.001 미만이라 **기본값 0.5를 유지**했습니다. 최적 임계값이 0.5와 거의 같은 것은 **가중치 1:2가 이미 판정 기준을 낮추는 역할**을 했기 때문입니다.

### 12-2. 최종 Test (1회)

Train 전체(36,155행)로 다시 학습하고, Test(9,039행)에 한 번 평가했습니다.

| 지표 | Train 5-fold (0.5) | **Test (0.5, 최종)** | 참고: Test (0.495) |
| --- | --- | --- | --- |
| PR-AUC | 0.4908 | **0.4957** | 0.4957 |
| F1 | 0.5165 | **0.5329** | 0.5311 |
| Recall | 0.5826 | **0.6040** | 0.6049 |
| Precision | 0.4640 | **0.4769** | 0.4734 |
| Accuracy | 0.8724 | **0.8761** | 0.8750 |

PR-AUC는 임계값과 관계없는 지표라 두 값이 같습니다. Test 결과가 Train 5-fold와 비슷해, 과적합 없이 일반화된 것으로 보입니다.

| 혼동행렬 (Test, 임계값 0.5) | 예측 no | 예측 yes |
| --- | --- | --- |
| **실제 no** (7,981) | 7,280 | 701 |
| **실제 yes** (1,058) | 419 | **639** |

- 실제 가입자 1,058명 중 **639명(60.4%)**을 찾았고, 419명(39.6%)은 놓쳤습니다.

- 혼동행렬 숫자는 Test 결과표(Recall 0.6040, Precision 0.4769)와 가입자 수(1,058명)로 계산한 값입니다.

### 배운 점

1. 불균형 처리(가중치 · RUS · SMOTE)는 PR-AUC를 올리지 못하고, Precision과 Recall의 균형만 바꿨습니다.
2. 성능을 가장 크게 올린 것은 모델이나 튜닝이 아니라 **데이터에 없던 시기 정보를 만든 파생변수**(하루 통화량, 누적 가입률)였습니다.
3. 상관계수가 작아도 구간별로 보면 가입률이 달라지는 변수(age, balance, campaign)가 있어, 상관계수만으로 변수를 고르면 안 됩니다.

### 한계

| 구분 | 내용 |
| --- | --- |
| 성능 | Test PR-AUC 약 0.5 수준으로, 실제 업무에 바로 쓰기에는 놓치는 가입자(39.6%)와 헛걸음 통화(52.3%)가 함께 많은 편입니다 |
| 시간 정보 | 연도는 행 순서로 **추정**한 값입니다. 누적 가입률은 사실상 "캠페인 시기" 정보라, 무작위 분할 평가에서는 유효하지만 **미래 데이터에서는 효과가 다를 수 있습니다** |
| 고객 식별 | 고객 ID가 없어 같은 고객의 반복 등장을 확정할 수 없습니다 |

### 인사이트

- 하루 통화량이 적은 **선별 통화일**의 가입률(35.1%)이 대량 통화일(4.5 ~ 7.2%)보다 훨씬 높습니다.
- 이전 캠페인에서 가입한 고객의 가입률이 64.7%로 가장 높아, 이 고객 위주로 선별해서 연락하는 전략이 효율적인 것으로 보입니다.

### 개선 방향 (더 있으면 좋을 데이터)

- **경제 지표 (금리, 고용률, 소비자 신뢰지수 등):** 시기 정보가 성능을 크게 바꾼 것으로 보아, 그 시기의 경제 상황을 직접 담은 정보가 도움이 될 것으로 보입니다. 같은 데이터의 확장판(UCI bank-additional)에는 이런 지표가 포함되어 있습니다.
- **고객의 금융 이력 (소득, 보유 상품, 거래 내역, 과거 예금 가입 이력):** 현재는 잔고와 대출 여부 정도만 있어 가입 여력을 판단하기에 정보가 부족합니다.
- **고객 식별 정보와 연락 이력:** 고객 단위로 연락 이력을 묶을 수 있다면 반복 연락의 효과를 더 정확히 볼 수 있습니다.
